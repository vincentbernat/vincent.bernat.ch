Comparés à des moteurs tels que [LaTeX][] ou [Typst][], les navigateurs ne disposent toujours pas d'un bon algorithme pour couper les lignes. La directive CSS `text-wrap: pretty` tente d'améliorer la situation, mais elle n'est toujours [pas implémentée dans Firefox][not implemented in firefox] et [produit d'étranges paragraphes étroits avec Safari][webkit-pretty]. [Plusieurs][kp1] [bonnes][kp2] [implémentations][kp3] de l'[algorithme de Knuth-Plass][knuth-plass] existent en JavaScript, mais elles provoquent un retard de l'affichage ou un changement intempestif de la mise en page. Ma solution consiste à insérer des césures conditionnelles et des espaces insécables à des endroits stratégiques pour obtenir un résultat potable mais prévisible. !!! Le « problème » le plus visible de ce paragraphe concerne le mot « _aigus_ » : il peut se retrouver seul sur la dernière ligne, voire être coupé. En anglais, il s'agit d'un « _runt_{lang=en} », mais je ne pense pas que nous ayons un terme spécifique en français[^runt]. Sans césure, ce cas est plus rare, mais la composition fait apparaître un grand blanc entre la fin d'une ligne et la marge droite, comme sur la deuxième ligne quand le paragraphe mesure 825 pixels de large. Quand le paragraphe est justifié, ces blancs se transforment en espaces plus larges entre les mots. Ces défauts donnent un aspect insatisfaisant au texte et sont à éviter[^short]. [^runt]: Diverses sources confondent ces lignes très courtes avec les veuves ou les orphelines. Dans « [The Elements of Typographic Style][] », Robert Bringhurst explique la différence entre veuves et orphelines, qui sont moins un problème pour le web en l'absence de pages : > Les lignes isolées créées quand un paragraphe _commence_ sur la > _dernière_ ligne d'une page sont appelées _orphelines_. Elles n'ont pas de > passé, mais elles ont un avenir, et elles ne doivent pas inquiéter le > typographe. Les bouts de paragraphe laissés quand celui-ci se _termine_ > sur la _première_ ligne d'une page sont appelés _veuves_. Elles ont un > passé, mais pas d'avenir, et elles ont l'air tronquées et abandonnées. [^short]: [Robert Bringhurst][The Elements of Typographic Style] fixe à quatre lettres la longueur minimale d'un mot isolé sur la dernière ligne, mais beaucoup préfèrent davantage. > _2.4.2._ Évitez de laisser en dernière ligne d'un paragraphe la fin d'un > mot coupé ou un mot de moins de quatre lettres. Le « [Lexique des règles typographiques en usage à l'Imprimerie nationale][] » fixe une règle proche : > La dernière ligne d'un alinéa doit comporter un mot ou une fin de mot de > longueur au moins égale au double du renfoncement de l'alinéa suivant. ![Coupure des lignes dans Firefox 160](self://media/images/line-break.svg#firefox){.lf1-line-break} Contrairement à Firefox, Chromium 157 implémente `text-wrap: pretty`. Il [corrige les paragraphes qui se terminent par un mot isolé sur la dernière ligne][pretty-chromium] en ajustant les points de coupure des quatre dernières lignes pour garder les deux derniers mots ensemble, comme « _sifflements aigus_ » dans notre exemple. ![Coupure des lignes dans Chromium 157](self://media/images/line-break.svg#chrome){.lf1-line-break} Comme Firefox, WebKitGTK 2.54[^safari] peut couper « _aigus_ » et laisser une ligne très courte en fin de paragraphe. Avec `text-wrap: pretty` et sans justification, il [produit souvent des paragraphes plus étroits][creates shorter paragraphs]. Sur cet exemple, avec la justification, WebKitGTK fait pire que tous les autres navigateurs, car il insère trop d'espace entre les mots. [^safari]: Le comportement devrait être identique à celui d'un Safari 26 récent, sauf peut-être pour le dictionnaire utilisé pour les césures. ![Coupure des lignes dans WebKitGTK 2.54](self://media/images/line-break.svg#webkit){.lf1-line-break} Ma solution consiste à insérer des **césures conditionnelles** ([U+00AD][shy]), sauf pour la fin du paragraphe, et des **espaces insécables** ([U+00A0][nbsp]) pour éviter une ligne trop courte en fin de paragraphe. Dans mon cas, j'ai fixé la limite à 8 caractères, ponctuation comprise. L'animation ci-dessous indique une espace insécable par un triangle violet et une césure conditionnelle par un trait vertical rouge[^debug]. Avec `hyphens: manual`, le navigateur peut couper une ligne là où se trouve une césure conditionnelle. [^debug]: Pour afficher ces marques sur n'importe quelle page de ce site, utilisez le raccourci ← ← s. ![Coupure des lignes dans Firefox 160 avec le texte prétraité](self://media/images/line-break.svg#preprocess){.lf1-line-break} Cette approche ne peut pas rivaliser avec un vrai algorithme de coupure des lignes, mais elle fonctionne dans Firefox, évite les paragraphes étroits de Safari et donne parfois de meilleurs résultats que Chromium, car elle autorise la césure de « _sif‐fle‐ments_ ». De plus, tous les navigateurs coupent les lignes aux mêmes endroits : avec `hyphens: auto`, chaque navigateur utilise son propre dictionnaire de césure et Safari ignore [`hyphenate-limit-chars`][hyphenate-limit-chars], tandis que chaque navigateur est libre du choix de l'algorithme pour `text-wrap: pretty`. Il est plus robuste d'appliquer les transformations au texte brut puis de réintégrer le balisage HTML dans le résultat. J'utilise la [bibliothèque `lxml`][lxml] pour analyser et manipuler le HTML. Parcourir chaque bloc et en extraire le texte est simple, mais tout le balisage interne est alors perdu : ```python for block in root.iter("p", "li", "h1", "h2", "h3"): text = typography("".join(block.itertext()), "en_US") ``` À la place, nous allons garder la position de chaque groupe de lettres lors d'un parcours en profondeur de l'arbre HTML. Par exemple, le texte de l'extrait HTML précédent se découpe en trois : ```python slots = [ ["p.text", 0, 'I have read "'], ["a.text", 13, "Dune"], ["a.tail", 17, '".'], ] text = "".join(slot[2] for slot in slots) ``` Les modifications du texte se traduisent en une liste de substitutions : position de début, position de fin et nouveau texte. ```python changes = [] for m in opening_quote.finditer(text): start, end = m.span(1) changes.append((start, end, "‘" if m[1] == "'" else "“")) for m in closing_quote.finditer(text): start, end = m.span(1) changes.append((start, end, "’" if m[1] == "'" else "”")) # changes = [(12, 13, "“"), (17, 18, "”")] ``` Pour appliquer une substitution, il suffit de retrouver l'emplacement concerné et d'en modifier le texte[^position]. [^position]: L'exemple ne montre que des substitutions de même longueur. Dans le cas général, il faut aussi mettre à jour les positions. ```python for start, end, new in changes: slot = next(slot for slot in reversed(slots) if slot[1] <= start) offset = start - slot[1] slot[2] = slot[2][:offset] + new + slot[2][offset + end - start :] # slots = [["p.text", 0, "I have read “"], # ["a.text", 13, "Dune"], # ["a.tail", 17, "”."]] ``` Un second parcours en profondeur réintègre les modifications dans l'arbre HTML, en corrigeant les nœuds texte qui ont été mis à jour. Le navigateur peut ainsi couper une longue adresse IPv6, telle que `2a01:e0e:c03c:f44e:dabc:7337:38fa:ff40`, ou un nom de méthode Python, comme `xxhash.xxh3_128_hexdigest()`. À ma connaissance, ce n'est pas possible uniquement avec CSS. ## Copier-coller Lors d'une copie de texte, certains navigateurs conservent les césures conditionnelles ou les espaces invisibles. C'est gênant lorsqu'on colle le résultat dans un terminal. Pour contourner ce problème, l'évènement « _copy_{lang=en} » est intercepté afin de retirer ces caractères spéciaux de la version `text/plain` placée dans le presse-papiers : ```javascript document.addEventListener("copy", (event) => { const selection = document.getSelection(); const raw = selection.toString(); const text = raw // SOFT HYPHEN, ZERO WIDTH SPACE .replace(/[\u00ad\u200b]/g, "") // NO-BREAK SPACE, NARROW NO-BREAK SPACE .replace(/[\u00a0\u202f]/g, " "); if (text === raw) return; const div = document.createElement("div"); for (let i = 0; i < selection.rangeCount; i++) div.appendChild(selection.getRangeAt(i).cloneContents()); event.clipboardData.setData("text/plain", text); event.clipboardData.setData("text/html", div.innerHTML); event.preventDefault(); }); ``` Les césures conditionnelles n'interfèrent pas avec les autres fonctionnalités, comme la recherche dans la page des navigateurs ou l'indexation par [Pagefind][].
